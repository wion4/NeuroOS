# Перенос инструментов C / ASM / C++

В v0.0.11 работает первая нативная компиляция C/GNU ASM → .nos внутри NeuroOS.
Сам compiler.nos собирается LLVM на Windows; самосборка не заявляется.

Для первого этапа изучен TinyCC: C-компилятор со встроенными ассемблером и линкером.
Он не решает задачу C++. Исходники включены без изменений в vendor/tinycc.
Основной сервер repo.or.cz завис при получении;
использовано явно обозначенное неофициальное зеркало https://github.com/TinyCC/tinycc.
Зафиксирован исследованный commit: e23dabed154a8495f3ac1ff3cc9d04fa1c207893.
Файл COPYING содержит LGPL 2.1; файлы содержат собственные copyright/license
уведомления. Все 554 файла исходного checkout, уведомления и хеши сохранены.
Разбор дробных чисел использует неизменённый floatscan из musl v1.2.5 с MIT COPYRIGHT;
адаптация строкового scanner и x87-функций находится в ports/musl и user/strtod.c.

Проверенные исходники: tcc.h, libtcc.c и tccrun.c. Они используют malloc/realloc/free,
stdio, string, errno, числовые преобразования, setjmp/longjmp, файловые дескрипторы
и ряд функций времени. Native-run и загрузка системных библиотек требуют дополнительных
функций памяти/динамической линковки: первый порт должен выпускать статический файл,
а не обещать JIT или совместимость с библиотеками Linux.

| Требование | Состояние |
|---|---|
| Изоляция, вход/выход из приложения | Есть, статический ELF64 .nos с ABI-меткой |
| x87/SSE и double | Есть, eager FXSAVE64/FXRSTOR64; AVX выключен |
| malloc/calloc/realloc/free | Есть, 16-байтовое выравнивание, куча до 2 МиБ |
| Файловые чтение/запись и seek | Есть начальные unbuffered FILE-потоки через IPC |
| Строки и форматирование диагностик | Есть; printf без дробных/wide-преобразований |
| setjmp/longjmp | Есть, проверены все callee-saved GPR, вложенность и значение 0 → 1 |
| open/read/write/lseek/fdopen | Начальный однопоточный адаптер через IPC; не полный POSIX |
| Заголовки компиляции и startup/runtime .nos | Predefs/startup, начальный SDK с 21 файлом и libnos.a |
| Размер самого компилятора | Около 263 КиБ, boot-модуль или файл данных; ELF 160 страниц, стек 64 КиБ |
| C++ | Отдельный последующий перенос готового toolchain |

Порт выполняет только статическую компиляцию и линковку, без JIT/host dlopen.
В ports/tinycc/prepare.py заданы адаптации: собственный target macro, фиксированная
эпоха __DATE__/__TIME__, page-aligned PT_LOAD, запись padding через seek и проверка
ошибок вывода. Vendor не модифицируется; build/*/tinycc-source/neuroos.patch содержит
применённые изменения. Собранный ELF проверяется тем же elf_validate, что и при запуске.
Выходной файл заменяется одной файловой транзакцией только после успешной сборки.

tests/test_compiler.py прошёл полную цепочку на отдельном диске: ввод C через редактор,
сборка/запуск C с глобальными данными и double, inline ASM и отдельного .s, ошибки
синтаксиса/линковки/лимита загрузчика, сохранность прежнего результата, перезагрузка,
повторный запуск всех трёх программ и побайтово одинаковая повторная сборка.

Хранилище v3 уже держит 128 файлов до 1 МиБ; установленный compiler.nos прочитан
с диска и скомпилировал работающую программу после холодной загрузки.
install-sdk устанавливает заголовки и libnos.a без замены существующих имён.
Компилятор ищет include в корне и подключает библиотеку при её наличии. В госте
проверены native printf/malloc/strtod/file API, холодная сборка установленным
компилятором и побайтовая воспроизводимость. Runtime пока собирается LLVM на хосте.
Дальше: процессы/supervisor и расширение SDK по потребностям приложений.
Адаптер FILE/fd пока один объект
на дескриптор, без dup, многопоточности, файловых ACL и каталогов; fdopen сужает права
этого объекта. stdin не реализован. Эти ограничения не скрываются под обещанием POSIX.
