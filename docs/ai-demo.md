# Offline inference prototype (0.0.18)

С 2026-11-04 развитие этого эксперимента отложено. Приоритет — ОС и универсальные
средства управления, проверяемые без модели; ИИ подключается в последнюю очередь.
Специальные вызовы прототипа не считаются окончательным control API.
Порядок работ и системные контракты — [system-control.md](system-control.md).

В этом этапе реализован настоящий forward pass маленького трансформера в
изолированном ring-3 процессе. GUI и диагностическая консоль обращаются к нему
через отдельный IPC-клиент. Математика не выполняется в ядре или на хосте.
Текст не захардкожен: разные запросы дают разные продолжения, а токены сравнены
с отдельным host-oracle на тех же весах через системную математическую библиотеку.

Тестовый профиль: stories260K из karpathy/tinyllamas, размерность 64, FFN 172,
5 слоёв, 8 query / 4 KV heads, словарь 512, контекст 512. Это учебный генератор
продолжений английских историй. Instruction following, русский диалог, инструменты,
долговременная память и Agent Manager ещё не реализованы. Конечную модель ОС
этот эксперимент не выбирает. Обучение или изменение весов не выполнялись.

## Воспроизводимость и лицензии

Нейронные блоки и BPE взяты из llama2.c commit
350e04fe35433e6d2941dce5a1f53308f87058eb. Полный исходный run.c, README и MIT
сохранены в vendor/llama2c; prepare.py извлекает нужные части и добавляет проверки
неудавшихся выделений. Исходный vendor файл не изменяется. Локальные добавления:
ограниченный загрузчик, IPC, проверка размеров/CRC/finite и приватная math-поддержка.

Модель и tokenizer закреплены на revision
0bd21da7698eaf29a0d7de3992de8a46ef624add; SHA-256 и размеры — models.lock.json.
Model card указывает MIT; его копия сохранена в vendor/llama2c/MODEL-CARD.md.
Веса не входят в Git. scripts/setup-ai-demo.py загружает только публичные .bin
и readme в игнорируемый tools/models/stories260k, проверяет SHA-256. .pt/pickle
не используется. Сборка с AI-флагом проверяет хеши, работает офлайн и создаёт
boot-пакет; при отсутствии активов сборка останавливается с инструкцией установки.

```powershell
python scripts/setup-ai-demo.py
$env:NEUROOS_AI_DEMO='1'
$env:NEUROOS_BOOTSTRAP_SDK='1'
python scripts/make_iso.py
```

VM должна быть выключена перед сборкой ISO. Без NEUROOS_AI_DEMO основной образ
и прежние инструменты собираются без весов и без обращения к сети.

## Память, права и протокол

airuntime.nos, aiclient.nos и ai.pack — дополнительные boot-модули 9/10/11.
Модель не хранится в пользовательском файловом сервисе: пакет 1,062,799 байт
чуть больше нынешнего лимита отдельного файла. Для прототипа он выдаётся runtime
через read-only capability, без изменения FS3 или диска. Это фиксированный профиль
boot-пакета; произвольный GGUF/model registry пока не поддерживается.

Runtime получает recv/send на приватных AI-endpoints и model-read cap 3 с ролью
(endpoint=3, rights=16). Системный вызов 17 возвращает размер при offset UINT64_MAX
или копирует до 4096 байт по проверенному offset. user_copy_to сначала проверяет
всю writable область; чужие boot-модули и физическая память недоступны. Чтение
в RX-страницу отклоняется. Обычные .nos, desktop и AI-клиент этого cap не имеют.
ATA/файловые права runtime не выдаются. Сам runtime проверяет эти запреты при запуске.

Пакет копируется в собственную NX-кучу. Строго проверяются размеры, профиль Config,
CRC32, не-NaN/Inf параметры, длины/границы tokenizer, наличие dummy-prefix token.
SHA-256 проверяется при сборке; CRC внутри пакета — контроль целостности, а не
подпись подлинности. Размеры аллокаций определяются фиксированным проверенным
профилем. Модель, KV cache и tokenizer помещаются в существующие 2 МиБ процесса.
Математические функции — приватный ограниченный x87/SSE набор для данного профиля,
с тестами против UCRT; полная libm не заявляется.

Запрос 64 байта: op/число шагов/до 55 ASCII-байт prompt. Ответы 64 байта передают
текст по 48 байт и trace по 12 token IDs, затем DONE с итоговыми размерами/статусом.
Клиент проверяет offsets/counts. Генерация greedy, до 96 forward steps и 1535 байт
ответа; интерфейс использует 48 шагов. Недостаточный бюджет для длинного prefix
возвращает ошибку. Оба процесса ограничены прежним CPU-бюджетом; runtime кэшируется
между запросами. Сбой уничтожает его адресное пространство; новый запрос может
создать процесс заново (до трёх рестартов). Запрос после ошибки не переигрывается.

## Пользовательский интерфейс

В образе с AI-флагом сверху появляется AI demo. Поле принимает английский prefix,
Generate запускает фоновое вычисление, Up/Down показывают ответ. Во время генерации
Notes/Files/Style продолжают работать. Ctrl+Alt+G запускает текущий prompt без
смены активного окна. Cancel завершает оба AI-процесса и освобождает их страницы;
следующий запрос начинает заново. Unload освобождает cached runtime; boot-пакет
остаётся частью образа. Закрытие desktop отменяет его активную генерацию.
Syscall 15 доступен только desktop: START копирует 64-байтовый запрос, POLL
возвращает 0, пока работа идёт, или 1 с полной 2000-байтовой сессией. CANCEL/UNLOAD
не принимают указателей. Ядро не хранит пользовательский указатель между вызовами;
неверный writable-буфер POLL не потребляет результат.

FS/desktop используют очереди 0/1, AI/runtime/client — отдельные 2/3. Модельные
процессы не получают доступ к файловой паре. Runtime cache меняет привязку cap
при переходе между фоновым GUI и прежним консольным путём. Ожидание сообщения
(syscall 16) блокирует задачу, проверив cap/длину/всю writable область; сообщение
или смерть отправителя будят её. Старый nonblocking receive остаётся доступен.
Desktop sleep (12) теперь усыпляет задачу, оставляя CPU другим пользовательским
процессам. Если runnable задач нет до ближайшего таймера, ядро выполняет HLT.

Обычные .nos не получают syscall 14/15/17; 16 требует receive-cap. На время
фонового AI старый foreground native launcher отклоняется с busy: общего
менеджера процессов и нескольких FS-клиентов пока нет. Синхронный syscall 14
сохранён как прежний путь, GUI использует новый 15.
Сервис не сохраняет prompt/ответ в файлы и не выполняет действий по тексту.

В консоли: ai PROMPT, ai-trace PROMPT (диагностические token IDs), ai-reset.
ai-fault — диагностическая инъекция настоящего user #PF в cached runtime.

Проверки: tests/test_ai_core.py, test_ai_guest.py, test_ai_desktop.py,
test_ai_background.py.
Проверяются реальные веса, точные token traces на трёх prompts, приватная math
в своём диапазоне, повреждения/границы/NaN, тёплый runtime, изоляция, #PF и restart,
выгрузка без утечки страниц, GUI с 128 МиБ и неизменность несохранённой заметки.
QEMU запускается с -net none. Это не доказательство работоспособности на физическом
оборудовании и не готовый системный AI-помощник.
