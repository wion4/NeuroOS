# Следующий формат файлового хранилища

Цель: хранить компилятор, набор заголовков и более крупные программы. Начиная с
v0.0.12 этот backend включён по умолчанию после отдельных host/QEMU-проверок. Архитектура
не меняется: вся файловая логика и дисковая политика находятся в user space.

Ограничения первой версии: 128 файлов по 1 МиБ, плоский корень, имена
до 15 символов, один управляющий клиент/транзакция. Каталоги и конкурентный доступ
не добавляются одновременно с заменой механизма хранения.

Вместо полного снимка всех данных — copy-on-write непрерывные extents и два корня.
Блок 4096 байтов, целевой виртуальный диск 64 МиБ. Первый 1 МиБ зарезервирован:
старые v1/v2-данные остаются нетронутыми. Два корня по 8192 байта занимают блоки
128..131, данные начинаются с блока 132. Корень содержит generation, параметры
формата, CRC32 и 128 записей по 32 байта: имя, длина, extent, capacity и CRC данных.

Изменение файла пишет новый extent. Commit сначала завершает данные и flush,
затем пишет неактивный корень и снова flush. До подтверждения не изменяется
активное дерево. Аллокатор учитывает ссылки обоих валидных корней и текущей
транзакции; блоки прежнего корня нельзя повторно использовать раньше времени.
Abort отбрасывает только черновые ссылки. Оборванная запись корня обнаруживается
CRC; при сомнительном исходе IO сервис прекращает обработку до нового mount.

Отдельный marker в секторе 1023 после первого успешного commit запрещает тихий
откат к старому v2 при потере обоих новых корней. Миграция разрешается только из
проверенного старого снимка или заведомо нового диска; неизвестный диск не форматируется.

Проверены 14 host-сценариев, в том числе 128 сочетаний места обрыва/частичного сектора/
write-back и write-through и 96 отказов многопайлового commit, файл 1 МиБ, 128 имён,
CRC и импорт v1/v2. Реальный гость
импортировал v2, сохранил старые исполняемые файлы, создал 1 МиБ и 40 новых имён,
пережил холодную загрузку и смерть сервиса в транзакции. Повреждение обоих корней
отказало без возврата к v2. Первые 1023 сектора исходного образа сохранились побайтово.

NEUROOS_FS_BACKEND=2 включает прежний backend только для исторических проверок.
NEUROOS_FS3_TEST=1 добавляет отдельный стресс-модуль/команду в тестовую ESP; в рабочий
ISO он не включается. tests/test_fs3_guest.py использует исключительно свой диск.
