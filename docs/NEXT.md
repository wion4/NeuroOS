# Продолжение разработки

Текущий этап: v0.0.13 (образ в работе; рабочая VM пока 0.0.12). Работают собственное ядро x86-64, изолированные ring-3 задачи,
таймерное переключение, IPC с правами, внешний файловый сервис, постоянные снимки,
миграция v1/v2 → v3 без перезаписи старых банков, 128 файлов до 1 МиБ,
транзакции, редактор исходников,
запуск .nos с диска, сохранение x87/XMM, динамическая память, начальная библиотека C
и нативный порт TinyCC: C/ASM → .nos в госте, запуск и холодная перезагрузка проверены.
runfs явно выдаёт приложению права файлового клиента; права портов диска остаются
только у сервиса. После смерти клиента открытая транзакция отменяется.

Исходная цель не достигнута: SDK начальный, нет C++, общего менеджера
процессов, графического окружения, локального инференса, истории диалогов,
агентного управления и набора приложений.

Нативный компилятор описан в toolchain-port.md; compiler.nos работает и boot-модулем,
и установленным файлом после холодной загрузки. install-sdk ставит 21 файл атомарно;
tests/test_sdk.py прошёл printf/malloc/strtod/files, защиту существующего заголовка,
чтение SDK и сборку установленным компилятором после холодного старта. Самосборки нет.
Следующий ограниченный шаг: завершить обновление образа 0.0.13, затем supervisor
файлового сервиса. Сохранять образ/размер boot-модуля для рестарта, не повторять
неподтверждённый запрос записи, ограничить число автоматических рестартов. Проверить
сбой в транзакции, восстановление на следующем запросе и прекращение цикла сбоев.

После первых инструментов: общий менеджер процессов и supervisor, ошибка ожидающему
клиенту при смерти сервиса, отзыв старых endpoint-прав, перенос консоли в user space.
ELF сейчас до 160 страниц сегментов, стек внешней программы 64 КиБ, куча 2 МиБ.
Архитектура микроядра согласована, повторное разрешение не требуется.

Не удалять vmware/data-flat.vmdk и data.vmdk при сборке: это пользовательские данные.
Тестовый диск QEMU — build/normal/data.img, отдельный от рабочей машины.
Не публиковать репозиторий; не трогать физические диски. Лицензия собственного кода
пока не выбрана. Git identity отсутствует; не выдумывать имя/email для коммитов.

Фактически выполненные проверки — validation.md. tests/check-release.py прошёл
17 service/ELF + 3 format + 3 stdlib + 4 ATA + 14 FS3 host-тестов, boot 128 МиБ и все семь
гостевых сценариев. tests/test_compiler.py отдельно прошёл нативную C/ASM сборку,
ошибки, холодный запуск и воспроизводимость результата.
