# Журнал событий нативных задач — 0.0.20

Programs → Events открывает read-only просмотр lifecycle обычных фоновых .nos.
Есть запуск, exit/fault/CPU limit, запрос Stop, отмена, rollback/закрытие файловой
сессии, восстановление FS, очистка результата и закрытие владельца. В таблице
также показаны пиковые наблюдённые owned pages и charged timer ticks.

Это волатильный журнал управляемых native jobs, не полный постоянный аудит ОС.
Старые CLI run/runfs, все файловые операции и ранние драйверы пока не включены.
Кольцо содержит последние 64 записи в течение одной загрузки, не пишет на диск
и не использует FS/модель. Перезапуск desktop не очищает кольцо; перезагрузка
ОС очищает. Нельзя сохранять cursor между загрузками без будущего boot identity.
Постоянный collector/boot ID, scoped subscriptions и журнал файловых действий
остаются следующими системными задачами до интеграции модели.

## API наблюдения

Формат 1 — user/events.h. Вызов 21 принимает pointer, sizeof(query)=560 и
reserved=0. Сейчас нужен фиксированный доверенный desktop/controller. Обычный
дочерний .nos, в том числе с файловыми правами, получает -1. Это административное
наблюдение native jobs текущей загрузки; отдельные agent grants ещё не выдаются.
Вызов только читает, не разрешает добавление, изменение или очистку событий.

Входные поля: version=1, capacity=1..8, after — последний прочитанный sequence.
Другие поля — outputs. next — cursor для следующего чтения, count — число записей,
oldest — первый ещё доступный sequence, lost — число затёртых непрочитанных записей.
Каждый читатель хранит свой cursor: чтение не удаляет записи и не мешает другим.
При старом cursor чтение начинается с oldest и явно возвращает lost. Cursor из
будущего/неверная версия/capacity/размер отклоняются, output не меняется.

До работы проверяется весь writable буфер. Пользовательский указатель не хранится
между вызовами. Неиспользованные записи ответа обнулены. Кольцо не выделяет память,
не выполняет IO и не блокирует задачу из-за медленного наблюдателя. Текущая
реализация — один CPU и writers/readers в kernel context с отключёнными IRQ.
Перед SMP нужны синхронизация и новая проверка согласованности snapshot.

Sequence никогда не оборачивается: при UINT64_MAX новые записи не добавляются,
ответ выставляет NOS_EVENT_EXHAUSTED; старые остаются читаемыми. Случай after=max
также корректен и не запускает wraparound loop.

## Запись 64 байта

| Поле | Значение |
|---|---|
| sequence | Монотонный номер записи в этой загрузке |
| ticks | Monotonic PIT ticks с начала загрузки, не UTC |
| job | Непрозрачный native job ID |
| owner | Логическая сессия controller, не PID и не имя пользователя |
| kind | Тип, существующие номера закреплены за format 1 |
| flags | Snapshot launch permissions; сейчас NOS_EVENT_FILES |
| value | Типизированный результат, описан ниже |
| cpu_ticks | Число начисленных ребёнку user timer ticks |
| pages | Максимум owned-page count, наблюдённый после ELF load/изменения heap |

Owned pages включают image/stack/page tables и heap. Не включают весь расход
ядра или временные аллокации loader. CPU ticks — диагностический
счётчик планировщика, не точный профайлер CPU/wall time. Фаза загрузки отражается
во времени между Requested/Started; с 0.0.21 её отдельный loader не начисляется
конечной программе. До Started её cpu_ticks/pages равны нулю. Ошибка loading
может сопровождаться FS closed/rollback даже при выключенном launch file grant:
временная read snapshot сессия тоже должна закрыться. См. [loader.md](loader.md).

value: exit code для Exited, вектор для Fault, отрицательный errno в 64-битном
представлении для Load failed/FS unavailable. Files closed: 1 означает rollback
открытого draft, 0 — открытой транзакции уже не было. Result cleared хранит
terminal kind; Owner closed — состояние job до закрытия владельца. Остальные
события используют 0, в том числе CPU limit (счётчик есть в cpu_ticks).

Журнал не содержит stdout, имён/содержимого файлов, аргументов, пользовательских
указателей или текста запросов. В kernel trap записываются только числовые
метаданные. По этому журналу нельзя обещать откат уже совершённого commit.

## Просмотр

Events показывает новые записи сверху; Up/Down, PageUp/PageDown, Home/End и Latest
управляют просмотром. Esc возвращает в Programs и не отменяет ребёнка. Окно
собирает ограниченную локальную копию последних 64 записей; missed означает
потерянные до чтения записи ядра, а не удаление событий другим читателем.
Длинные числа ограничены шириной столбца с '+', API сохраняет полные 64 бита.

Тесты: test_journal.py (настоящий C, включая UINT64_MAX), test_job_control.py
(настоящий ring 3, authority/version/buffers, lifecycle values, CPU limit=1000,
heap peak, fault, rollback, overwrite), test_event_desktop.py (GUI, busy FS,
переполнение и повторный controller), test_native_recovery.py (реальный PIO #PF).
