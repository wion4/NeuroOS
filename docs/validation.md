# Проверки NeuroOS

## 2026-11-04 — основа управления без модели: владелец транзакции FS3

`tests/test_fs3.py`: PASS всех 18 тестов, включая четыре новых. Backend принимает
доверенную 64-битную client identity отдельно от содержимого запроса. Другой
клиент и legacy-wrapper не видят draft и не могут выполнить операции/commit/abort
чужой открытой транзакции; отказ не выполняет IO. Callback закрытия откатывает
только транзакцию её владельца, не пишет диск и не снимает poisoned-состояние
после неудачного commit. Разные полные tokens с совпадающей младшей частью не
смешиваются. Обычные autocommit операции освобождают владение.

`receive_wait_from` читает sender из RDX ответа ядра; ramfs3 передаёт его backend.
На реальном текущем IPC sender — индекс задачи, а FS-сессия одна. Проверка разных
generation-like tokens выполнена на host backend; устойчивые сессии ядра и
автоматическое уведомление client-closed пока не реализованы. Эта подготовка не
объявляется готовым многоклиентным FS или менеджером процессов.

Без AI-модулей повторно прошли boot128 и ring3/services selftests, file SDK с
правами/rollback/PMM, supervisor с mid-PIO fault и cold persistence, guest FS3
с legacy import, файлом 1 МиБ, >8 файлов, аварией транзакции и fail-closed при
повреждении обеих roots. Все образы тестовые; рабочий диск VMware не использован.
Отчёт: build/system-control-foundation/result.json. Рабочий ISO остаётся v0.0.18.

## 2026-11-03 — v0.0.18: фоновая генерация и блокирующее IPC

Полный `tests/check-release.py --desktop --ai`: PASS всех 19 этапов: прежние
host/boot/SDK/libc, текст/два GUI-прогона, AI core/guest/GUI и новый background.
Старый nonblocking IPC сохранён. Fsclient дополнительно проверяет blocking
receive: cross-page writable rejection оставляет допустимый префикс нетронутым,
короткий буфер не потребляет сообщение, затем полный receive получает его.
AI-клиент проверяет cap, RX destination и длину до ожидания сообщения; реальная
смерть runtime будит ожидающего клиента и позволяет следующему запросу восстановиться.

`tests/test_ai_background.py`: PASS с 128 МиБ, без сети и настоящими весами.
QEMU icount6 делает пересечение вычисления и GUI наблюдаемым: запись Notes
завершилась раньше AI GUI COMPLETE. Байты независимо прочитаны с диска FS3.
Проверены Escape/cancel, fresh generation, cache из фоновых очередей 2/3 обратно
в консольные 0/1, закрытие desktop с активной генерацией и освобождение обоих
адресных пространств. После ai-reset физические страницы точно вернулись к
исходному числу. Тест предварительно форматирует только свой пустой диск при
обычной скорости, чтобы искусственный icount не исчерпал CPU-бюджет импорта.

После полного прогона исправлен внутренний return сеанса: намеренно оставленный
AI cache теперь учитывается отдельно от утечки. Тот же background-тест повторно
прошёл на итоговом коде, проверив DESKTOP EXIT CLEAN и с cached runtime, и с
отменой активной работы при выходе. В синхронных путях без кэша счётчик не меняется.

На финальной сверке compiler.nos отличался между build-вариантами из-за __FILE__
подготовленного upstream исходника. Добавлен prefix-map в стабильный vendor/tinycc;
исходники vendor не изменяются. После этого заново прошёл полный test_compiler.py:
C/ASM, структуры/double, ошибки без замены прежнего output, встроенный/установленный
компилятор, четыре холодных старта и одинаковые байты повторной компиляции.
Новый test_build_variants.py проверяет десять user ELF LOAD payloads, model pack,
объект scheduler и полное совпадение compiler.nos в трёх конфигурациях. Он добавлен
следующим, двадцатым этапом --ai; исходный полный прогон выше содержал 19 этапов.
Отдельный прогон этого нового этапа — PASS. На итоговом коде также повторно прошли
supervisor, SDK и guest FS3: mid-PIO #PF/reset, лимит рестартов, сохранённые данные
после cold boot, установленный SDK, файл 1 МиБ, >8 файлов, crash rollback и
отказ от старого snapshot при повреждении обеих новых roots.

Итоговый ISO 0.0.18 (5,259,264 байт) загружен в рабочей VMware: свежий serial
подтвердил startup selftest, FS3, SDK, AI modules и DESKTOP READY. Из ISO проверены
все packaged payloads. LOAD-сегменты десяти user-программ, process.o, ai.pack и
полный compiler.nos совпали с тестовыми конфигурациями. Приложения и инференс
интерактивно проверены в QEMU; в VMware подтверждена загрузка тех же payloads.
После загрузки все 25 файлов и весь data-flat.vmdk остались побайтово равны
SHA-проверенной резервной копии. ISO SHA-256:
7a6de12b838ac69ddc46bd37ddf6c05d8bc0a15b26fab04d992d1f82aef047bd.

Не заявляется общий менеджер процессов: foreground .nos по-прежнему приостанавливает
desktop, а его запуск во время AI отклоняется busy. FS имеет одного активного

sleep не блокирует других runnable задач; ожидающие receive не расходуют CPU
опросом очереди. Пределы модели и права — ai-demo.md.
